# AI 웹 검색으로 공식 도메인 확인

## 실제 QR 분석 경로

POST /api/analyze는 include_ai=true(기본값)일 때 매 스캔마다 BAZE Responses API의 web_search로 공식 소유 관계를 확인합니다.
고정 official_domains.json을 조회해 공식·사칭 여부를 정하지 않습니다.
상표명이 없어도 도메인 자체로 운영 기관을 검색하며, OCR/직접 입력한 상표명은 검색의 참고 정보입니다.

1. 기존 URL 형식·단축 주소·IP 주소·매장·TLS·생성일·국가 검사.
2. 페이지 검사를 요청했다면 제한된 HTTP 이동 확인과 정적 페이지 행동 분석.
3. 원래 주소와 최종 주소의 서로 다른 호스트 최대 2개를 한 번의 AI 요청으로 묶어 검색.
4. 실제 검색 호출 완료 여부, 반환 호스트 수·중복, 공식 도메인의 경계, 검색 출처를 서버에서 검증.
   AI가 판정은 했지만 출처가 검사 대상 사이트뿐이라 근거 부족으로 떨어지면, 시간 여유(전체 50초 안, 15초 이상 남음)가 있을 때만
   "다른 도메인의 출처를 찾으라"는 안내를 붙여 한 번 더 검색합니다. 재검색에서 근거를 갖춘 답만 받아들이고, 아니면 첫 결과(unknown)를 유지합니다.
5. 검증한 도메인 결과를 종합 점수와 프론트 공식 도메인 항목에 반영.

설정은 기존 BAZE_API_KEY / BAZE_BASE_URL / BAZE_MODEL을 사용합니다.
별도 검색 키는 필요 없습니다. 현재 키와 gpt-6-luna에서 실제 검색 기능을 확인했습니다.
다른 도메인 검색용 GPT 모델은 선택 설정 BAZE_DOMAIN_MODEL로 지정합니다.
모델/기관별 검색 권한이 없으면 unknown으로 반환하며 모델 기억·고정 JSON으로 대체하지 않습니다.
검색은 모델 토큰 외에 별도 사용량이 발생할 수 있습니다.

## 결과 및 점수

url_analysis.brand_domain과 final_url_analysis.brand_domain에 아래 필드가 들어갑니다.

- status: matched / mismatched / unknown
- source: ai_web_search
- ai_status: generated / disabled / skipped / unavailable
- brand: 검색으로 식별한 기관·상표명 또는 null
- official_domains: 검색에서 확인한 공식 도메인 후보
- reason: 판단 이유
- sources: 실제 검색 결과에서 확인한 출처 URL
- legal_status: 항상 not_assessed

matched는 소유 관계 근거가 있는 공식 주소 판정이며 해당 항목 가산 0점입니다.
mismatched는 검색으로 확인한 기대 상표의 공식 도메인과 QR 주소가 다르면 종합 점수에 50점을 한 번 가산합니다.
사용자가 상표를 확인했다면 그 상표의 공식 주소를 검색합니다. 스타벅스 포스터 → naver.com도 불일치입니다.
상표 입력이 없으면 호스트에 나타난 구체적인 상표를 식별해 실제 공식 주소를 검색하고 유사 주소를 비교합니다.
의심 도메인이 검색되지 않는다는 이유만으로 확인 불가로 만들지는 않습니다. 공식 비교 기준의 검색 근거가 필요합니다.
무관한 정상 사이트도 포스터와 불일치할 수 있으며, 불일치는 사기·불법 확정이 아닙니다.
상표 입력이 없는 일반 대행/예약 사이트를 무조건 사칭이라고 판단하지 않습니다.
인쇄 주소가 이 공식 주소와 같아 동일한 불일치를 반복하면 인쇄 불일치 25점은 중복 가산하지 않습니다.
unknown은 추가 점수 없이 검사 미완료로 남기며 다른 위험 신호가 없다면 최종 등급도 확인 불가입니다.
이미 관찰한 다운로드·사칭·차단 등의 위험은 unknown 때문에 내려가지 않습니다.
AI가 공식으로 확인한 주소에는 일반 단어가 포함됐다는 이유만으로 도메인 의심 단어 점수를 추가하지 않습니다.

인용 URL은 실제 web_search_call 또는 검색 인용 결과에 존재해야 합니다.
공식 조직·정부·공시기관의 1차 출처와, 대상 등록 도메인 밖의 근거를 요구합니다.
공시기관 출처 신뢰 범위에는 금융감독원(fss.or.kr)과 한국거래소(krx.co.kr)가 포함됩니다. 이는 판정 대상 상표 목록이 아닙니다.
모델이 근거 없이 공식이라고 답하거나, 자기 사이트 소개만 근거로 제시하면 unknown으로 내려갑니다.
이 검증은 출처 존재와 구조를 확인하는 장치이며 출처의 내용·소유권을 법적으로 증명하지는 않습니다.
소유 관계가 확인되어도 합법성·악성코드 부재·서비스 전체 안전을 보장하지 않습니다.

## 외부 전송 및 제한

- 호스트명과 최대 5개·각 60자 이하의 상표 힌트만 이 검색 요청에 전송합니다.
- QR 경로·쿼리·토큰·프래그먼트·사진은 이 요청에 포함하지 않습니다.
- 외부 검색 제공자는 검색 과정에서 공개 페이지를 조회할 수 있습니다.
- 휴대폰은 의심 주소를 자동으로 열지 않으며, 서버가 검색 출처를 별도로 다운로드하거나 실행하지 않습니다.
- 내부망 차단 대상이면 외부 도메인 AI 요청도 건너뜁니다. IP 주소·로컬 전용 이름은 검색하지 않습니다.
- 요청마다 새로 검사하며 애플리케이션 결과 캐시는 사용하지 않습니다.
- 도구 호출 최대 2회, 낮은 검색 문맥, 출력 최대 2,000토큰, 전체 시간 약 36초 상한입니다.
- 검색 실패·시간 초과·불완전 응답·출처 부족은 unknown입니다.

## 두 API의 차이

POST /api/analyze: include_ai=true 기본값. 프론트에서 현재 이 경로를 사용하므로 별도 요청 필드 변경 없이 작동합니다.
include_ai=false이면 행동 분석·공식 도메인 검색·설명 AI를 모두 호출하지 않습니다.

POST /api/url/analyze: 기존 로컬 검사 용도를 위해 include_ai=false 기본값을 유지합니다.
이 경우 공식 도메인은 unknown이고 고정 DB로 비교하지 않습니다.
include_ai=true를 명시하면 동일한 AI 검색을 수행합니다.
resolve_redirects=true도 명시하면 확인한 최종 주소를 함께 검색합니다.
매장 QR 등록 DB 비교는 도메인의 공식성 검색과 별도 기능으로 유지됩니다.

official_domains.json은 기존 OCR 후보 별칭/표시와 레거시 오프라인 검사 함수·테스트에 남아 있습니다.
HTTP QR 분석 경로는 compare_brand=False 및 빈 brand_words를 사용하므로 그 파일을 공식 판정 근거로 읽지 않습니다.
OCR 응답의 registered는 예전 별칭 목록에 있는지 표시하는 호환 필드이며 AI 검색 가능 여부가 아닙니다.
앱에서는 등록 여부와 무관하게 상표 후보를 선택해 검색할 수 있습니다.

## 확인한 동작

실제 BAZE 검증 모듈 실행에서 kakao.com은 카카오 기업 공시/공식 자료를 출처로 matched가 반환됐습니다.
같이 검사한 kaka0.com은 공식 여부·사칭 근거가 부족해 unknown이 반환됐습니다.
모델과 검색 결과는 실행마다 달라질 수 있으며 이 예시를 전체 정확도로 해석하지 않습니다.
합성 검색 응답을 사용한 API 회귀 테스트에서는 DB에 없는 상표의 근거 있는 사칭 판정이 50점으로 이어지는지 확인합니다.

테스트:

~~~powershell
.\.venv\Scripts\python.exe -B -m unittest tests.test_domain_ai
~~~

## 2026-11-14 포스터 회귀 검사

- naver-event.xyz → 네이버 공식 도메인 불일치, 기본 50점.
- 스타벅스 상표 확인 + naver.com → 기대 상표와 불일치, 기본 50점.
- www.naver.com 인쇄 + m.naver.com QR → 등록 도메인 일치, 이 항목 0점.
- 스타벅스 및 starbucks.co.kr 인쇄 + starbucks-event.example.com QR → 불일치, 기본 50점.
- 다른 독립적인 위험 신호가 관찰되면 종합 점수는 추가될 수 있습니다.
- 인쇄 주소 일치는 그 주소가 공식이라는 인증이나 사이트 전체 안전을 뜻하지 않습니다.
- 프론트는 OCR domains[].domain을 printed_domains로 전달합니다. 상표를 선택하지 않아도 인쇄 주소는 전달됩니다.
- QR 사진으로 상표·주소 찾기를 켜고 포스터 글자까지 포함하거나 추가 정보에서 사진을 읽어야 합니다.
  QR 무늬만 실시간 스캔한 경우에는 포스터 상표/주소가 서버에 전달되지 않습니다.
- 네 사례의 API 회귀 검사는 검색·메타데이터 응답을 통제한 테스트입니다.
  실제 BAZE 검색으로 1·2·4번 불일치, 3번 모바일 네이버 일치를 별도로 확인했습니다.
  기존 스타벅스 테스트 이미지의 실제 AI OCR도 성공했습니다.
  사용자 첨부 표의 원본 포스터 전체를 휴대폰에서 재촬영한 검사는 아직 수행하지 않았습니다.
- 검색 권한/타임아웃/근거 부족은 여전히 확인 불가이며, 인쇄 주소 일치만으로 이를 정상으로 덮지 않습니다.
